# L3 Capstone — Ship a Spec-First Backlog Item

**Goal:** demonstrate you never start multi-file work without a plan — the L3 "move on
when" bar. This capstone produces a **real deliverable**: a shipped, spec-first change
touching more than three files.

See the annotated [golden example — a good spec](../examples/spec.md) for the bar on step 2.

## The exercise

Take a real backlog item that touches **more than 3 files** and ship it end-to-end using the
Context → Plan → Implement workflow:

1. **Context** — `@`-reference the relevant files; have AI analyze current behaviour. No
   edits yet.
2. **Spec** — write (or have AI draft, then you refine) a short specification of the desired
   outcome and constraints.
3. **Plan** — open Plan mode, generate the implementation plan, and **push back** on it
   before approving. Record at least one thing you changed in the plan.
4. **Implement** — only after the plan is right, execute. Review the diff against the spec.

## Passing bar

- A written spec and an approved plan exist *before* any code was written.
- The shipped change touches >3 files and matches the spec.
- You can name at least one problem the planning step caught that diving straight in would
  have hit.
- The diff is surgical — no unrequested changes snuck in during implementation.

## Deliverables

- The written **spec** (problem, outcome, acceptance criteria, non-goals).
- The approved **plan**, with a note on at least one thing you changed before approving.
- The **merged PR**, diff reviewed against the spec.

Attach the spec, the plan, and the merged PR as evidence.
