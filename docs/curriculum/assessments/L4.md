# L4 Capstone — Shared Automation (gated by an eval) + Security CTF

**Goal:** show you can multiply a *team's* output with shared automation you trust enough to
gate on, and that you carry the security mindset that L4's auto-executing hooks demand — the
L4 "move on when" bar.

## Part 1 — Team-shared command or skill, gated by an eval

Build and ship a custom command or skill that your team actually adopts, **and back it with a
small eval suite that gates it**:

- It codifies a real, repeated workflow (review checklist, scaffolding, a domain task).
- It's packaged and distributed so teammates install it, not copy-paste it.
- At least one other engineer uses it and it produces consistent output for them.
- A **small eval suite** (a handful of chosen cases + criteria) checks the skill still does its
  job, and would fail a regression. See the annotated
  [golden example — a good eval](../examples/eval.md) for the bar.

Evidence: the command/skill source, the distribution mechanism, confirmation of a teammate
using it, and the eval suite with its pass/gate output.

## Part 2 — Security CTF

Complete the **OWASP finbot CTF** (https://owasp-finbot-ctf.org) — a hands-on capture-the-flag
against an AI/agentic application. It drives home prompt injection, untrusted content, and
over-permissioned tools from the *Security Basics* reading, at the depth L4 needs.

## Passing bar

- The shared command/skill is in real use by someone other than you.
- The eval suite runs, has at least one case that would fail on a regression, and gates the
  skill (a red eval means "don't ship").
- You completed the CTF and can describe, in your own words, the class of vulnerability
  behind each flag and how you'd defend against it in our own agent workflows.
